## 1. 目标和已确认的产品范围

保留现有课堂助手能力，完成体验、稳定性和跨平台能力的大版本升级，处理现有 issues 与分支中的有效工作，并交付微信小程序的基础能力。

用户已确认：

- 小程序指微信小程序。
- 小程序需要支持只带手机上课、独立使用 BYOK，也要支持连接电脑上的本地模型。
- 目前没有小程序 AppID、服务端或域名；先交付可本地验证的版本。
- 允许大幅重构、改善前端和增加有价值的功能，但原有功能应保持可用。
- 最终目标是发布大版本。功能实现、安装包验证和微信正式上架分别记录，不能互相替代。

本提案建议版本为 `2.0.0`，保留「课狐 ClassFox」品牌、紧凑悬浮窗和课堂即时辅助定位。

## 3. 架构选择

### 3.1 推荐：保留技术栈，重建核心边界

保留 Tauri 2 + React + TypeScript + TailwindCSS、FastAPI/Python。使用 Python 3.12 和 `uv` 管理依赖，Node 22 LTS 和 `pnpm` 管理前端；实际引入的版本、平台支持、license、API 和依赖体积在实现对应任务前核对并锁定。现有有效依赖不因升级本身而全部换新。

新增原生 TypeScript 微信小程序，复用与运行环境无关的协议和状态定义。桌面 UI 与小程序各自使用适合其平台的界面，不引入另一套大型跨端框架。

另两条路径的取舍：

- 全部改写为 Rust 后端：减少 Python 运行时，但会同时替换 ASR、资料解析和打包链路，扩大兼容风险；本次不选。
- 统一托管云后端：手机可集中接入，但引入服务器运维、用户身份和密钥托管；用户当前没有对应资源，首版优先直连预设 BYOK 服务商。

### 3.2 数据与课堂生命周期

- 使用 SQLite 保存 `sessions`、`transcript_entries`、`materials`、`summaries`。每堂课独立 ID，原文追加保存，滚动摘要仅作为上下文缓存，不能替换原文。
- 统一时间戳为带日期和时区信息的值；查询按所属课堂与时间范围执行。
- 使用明确的课堂状态：`idle`、`starting`、`recording`、`paused`、`stopping`、`error`。后台任务绑定课堂 ID，过期 ASR 回调和摘要不能写入其他课堂。
- 停止录音立即完成设备释放和记录提交；总结作为独立任务，失败可重试。程序关闭走有界的正常退出流程。
- 旧 `data/`、课堂文件、笔记、引用资料和 `.env` 做显式、可重复执行的导入。保留原文件；不重写用户原 `.env`。已经在旧版本中被压缩掉的原文无法恢复，迁移说明必须写明。
- 资料以受控 ID 查找路径，限制扩展名、体积和解压资源，临时文件互相隔离；解析在不阻塞 API 的执行路径中进行。

### 3.3 模型与密钥

- 将 ASR 与 LLM 两类配置分开。用户选本地模型或 BYOK 后，界面明确显示「可用」「需下载」「配置无效」「设备不可用」等实际状态。
- 离线 ASR 候选为 `sherpa-onnx` 的中文/中英模型；本地 LLM 候选为应用管理的 `llama.cpp` 运行时和小型量化模型。先通过目标平台安装及实际样本验证，再确定默认模型；不承诺所有硬件都有相同速度。
- 一键安装包括运行时与权重、下载进度、空间检查、取消/重试、完整性校验和可用性测试。只有下载完成且加载测试成功才显示已安装；不把打开外部下载网页当成安装完成。
- 下载来源与版本使用固定清单，校验摘要；安全解压，不执行远端 shell 脚本。运行时只由本应用管理，已有 Ollama/OpenAI-compatible 服务可作为 BYOK/自定义端点连接。
- 桌面密钥优先使用系统凭据存储，界面只显示是否已配置和更新入口。未配置 key 时，应用仍能启动、管理课堂和使用已安装的离线能力。
- 小程序 BYOK 默认只在当前使用会话中保留；课堂文字保存在用户设备。首版不由项目方接收或代存用户 key。正式版服务域名需要在小程序后台预配置，不能将任意 URL 输入框描述为可直接访问所有服务。

### 3.4 API、音频和响应速度

- FastAPI 使用应用工厂和 lifespan 管理依赖、后台任务、ASR 与 LLM 客户端，避免模块导入时创建会话和写用户目录。
- 桌面默认只监听 loopback；启动时使用应用持有的随机访问凭据。HTTP 和 WebSocket 都验证身份，CORS 与 CSP 使用实际所需的来源。
- 增加版本化 API，核心对象使用类型化请求/响应。旧端点在可安全保留处通过适配层迁移；新增鉴权、配置响应脱敏等安全变化明确列入 2.0 升级说明。
- LLM 统一配置连接超时、首字/总时限、错误分类和有界重试。凭据错误、限额、断网和取消不能被包装为成功回答。
- 救场先输出简短可读内容，再继续补充；最近转录和引用资料使用有界上下文。自动预生成会消耗用户额度，首版不默认启动，可在有测量证据后增加显式选项。
- 音频采集与识别解耦，使用有界队列；设备错误、断网和识别线程退出要反馈到会话状态。手机音频也进入相同的后端处理入口。

### 3.5 桌面体验与跨平台

- 保留紧凑置顶条，完整工作区包含课堂实时记录、资料、历史笔记和设置。统一字体、间距、圆角、状态与键盘交互；录音状态持续可见。
- 首次启动用短向导选择本地/BYOK、检查麦克风、测试模型连接，再开始课堂。错误提示说明影响和可执行的恢复动作。
- Tauri 负责资源定位、系统数据目录、窗口、进程与系统集成。后端状态就绪依赖带身份的健康检查，不能仅以端口可连为准。
- 只停止本实例启动并持有的进程。已有端口被占用时选择可用端口或给出明确错误，不能杀掉占用者。
- macOS 将可写数据置于 Application Support；包内资源只读，构建时配置麦克风用途声明和签名。Windows 使用用户数据目录，兼容中文路径和空格。
- 统一构建脚本和版本源。目标安装包为 Windows x64、macOS arm64/x64；每个目标分别核对原生依赖和构建结果，不用单机编译结果代表三平台通过。

### 3.6 微信小程序首版

两个连接模式：

1. **手机独立 BYOK**：手机采集音频，直接连接已支持且符合微信域名配置要求的 ASR/LLM 服务商。基础功能为转录、关键词提醒、救场、进度、总结、历史和导出。ASR 和 LLM 可以分别配置，不能只有文字聊天却称为课堂录音可用。
2. **连接电脑**：用户在桌面明确开启配对，通过短时配对码和桌面确认连接；小程序使用电脑 ASR/LLM，电脑保持运行且处于同一可互通局域网。手机只获得自己的课堂范围权限，不能访问桌面设置、key、其他课堂或模型安装接口。

局域网配对还需要安全传输设计：公有 Wi-Fi 上不能仅以明文 HTTP 的 bearer token 宣称安全。实现时选择受验证的加密配对/传输方案，或要求受信的 HTTPS 端点；此项是小程序接入真实课堂数据的验收门禁。

微信支持同网段 HTTP/WS 连接，也提供 ONNX 推理接口，但这不构成手机上完整运行本项目 ASR+LLM 的性能证据。首版不承诺手机离线大模型。录音需处理权限拒绝、来电/系统中断、单段上限、退出前台与恢复；不宣称任意后台状态下可持续监听。

当前无 AppID：交付源代码、TypeScript 构建、模拟微信 API 的行为测试、独立 BYOK 请求的本地模拟服务测试、开发者工具导入说明和上线配置清单。正式域名、真实手机权限/录音、真机配对与微信审核需对应资源到位后验证，不能标为已完成。

## 5. 容易遗漏的验收边界

- 同一后台任务返回时，原课堂已经停止且新课堂已开始：不得串课或覆盖新状态。
- 模型下载中断、哈希不符、磁盘满、设备断开：不得显示成功，不破坏已有可用模型或课堂记录。
- 无 key、无麦克风、端口被其他程序占用：应用能启动到可恢复的状态，不影响其他应用。
- 小程序用户或连接 token 变化：不得获得之前用户的课堂、桌面管理权限或配置。
- 云端生成失败：录音已停止、原文已保存；UI 能独立重试总结，不生成伪成功笔记。

## 6. 发布前外部条件

- 微信 AppID 与平台配置目前不存在，正式真机发布与上架不在当前可验证条件内。用户确认先交付本地版本，不将其称为已上架。
- Apple Developer ID、签名与公证资源尚未确认。实现并验证构建路径后，再处理实际发布凭据；不要求在聊天中提供秘密，不通过关闭 Gatekeeper 代替签名。
- 真实 BYOK 服务验证需要用户通过安全配置提供可用服务；在此之前只报告模拟 provider、公开本地模型及无密钥路径的证据。
- 局域网的校园网络可能隔离设备；必须在实际可互通网络中测试，不能仅凭模拟请求断言真机可连。
